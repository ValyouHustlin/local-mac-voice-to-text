## Native target

Gesture: post an `fn` flags-changed press, play a synthetic spoken sentence
through the Mac, then post `fn` release.

Observed daemon receipt:

```text

→ 0.95s · <transcript>
```

Observed result: text appeared visibly in the TextEdit document at the cursor.
The opening words were materially wrong and the small default model
hallucinated unrelated wording. Cursor injection worked; transcript accuracy
did not meet the daily-use bar.

## Browser target

Target: a local-only textarea served from
`http://127.0.0.1:18765/parrot-browser-test.html` and controlled in the
connected browser.

Gesture: focus the textarea through browser automation, post `fn`, capture, and
release.

Observed daemon receipt:

```text
● recording
○ captured 8.19s · rms 0.020
→ 0.27s · <transcript>
```

Observed result: the local textarea remained empty. The browser control surface
did not become the macOS foreground application, so the generated cursor event
went to the foreground terminal instead. This is a verification limitation,
not proof that browser insertion itself fails. Browser end-to-end behavior
remains unverified.

The microphone captured unrelated ambient speech during this attempt. Further
ambient recording stopped immediately. The temporary WAV and screenshots were
deleted rather than retained.

The complete string appeared visibly on line 1 with the caret at the end.
This verifies direct Unicode insertion in this Electron target. Full

privacy stop.

## Defects and limits found

1. The default `whisper-base.en` model was not accurate enough in the observed
   native run.
2. The current app has no history, so a wrong target or blocked insertion can
   lose the transcript.
3. Direct Unicode insertion has no acknowledgment and cannot distinguish
   success from a dropped event.
4. The runtime allows a new recording while a previous transcription task is
   still active.
5. The inherited sanitizer removes every parenthetical, bracketed, or starred
   phrase, including legitimate technical text.
6. The event tap does not re-enable itself after macOS disables it.
7. Browser end-to-end behavior still needs a foreground-target receipt.
8. LaunchAgent TCC identity remains unverified.

## Ground-truth conclusion

The baseline is a working prototype, not a Wispr Flow replacement. Native
capture, local transcription, and cursor insertion were observed, but accuracy,
recoverability, state ownership, insertion acknowledgment, and multi-target
verification do not yet meet the product bar.
