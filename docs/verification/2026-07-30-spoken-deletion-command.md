# Bounded spoken deletion verification

Date: 2026-07-30

## Product contract

Wordhand can delete one exact phrase earlier in the current dictation with:

```text
command correction, delete <target phrase>
```

The command must be one final standalone clause after a nonempty,
punctuation-ended body. The target is limited to 1–8 lexical tokens and 80
characters and must have exactly one case-insensitive Unicode token-bounded
match. The engine reads no application text, cursor, selection, clipboard, or
surrounding document.

An accepted command removes only the target plus one adjacent horizontal-
whitespace run. Sentence-tail deletion keeps the existing `.`, `!`, or `?`.
Sentence-initial, newline, comma, colon, semicolon, or dash boundaries remain
literal rather than requiring capitalization or punctuation guesses. A command
also remains literal if it would remove the affected sentence's final lexical
content or if its target begins with another reserved editing verb.

Missing, repeated, overlapping, subword, partial-decimal, dotted-identifier,
emptying, malformed, embedded, quoted, question, oversized, and nonterminal
commands fail closed byte-for-byte. Rejection bypasses every formatter and
emits only the existing text-free reason and visible
`correction not applied · text preserved` notice.

## Oracle-first evidence

Four pure deletion tests were added before implementation. The red command:

```text
WORDHAND_SAFE=1 swift test --filter \
  'deletesOneExactUniquePhraseWithoutRewritingTheRemainingBody|\
deletionRemovesOnlyTheTargetAndOneAdjacentWhitespaceRun|\
deletionRequiresOneExactUniqueBoundedTargetAndAUsableResult|\
unsafeOrMalformedDeletionCommandsFailClosedByteForByte' \
  -Xswiftc -warnings-as-errors
```

failed to compile because the engine had neither a sentence-emptying rejection
nor an unsafe-boundary rejection. After implementation, the complete editing
engine passed 14 tests in one suite after 0.023 seconds. A focused integration
gate passed 22 tests across six suites after 0.026 seconds, covering existing
spoken-repair ordering, all four writing profiles, formatter bypass, raw and
processed History separation, History-before-insertion, and text-free
diagnostics.

The real public CLI formatting flow was then driven from the built executable.
Casual and the on-device Formatted path both returned exactly:

```text
Send the proposal Friday.
```

for `Send the obsolete proposal Friday. Command correction, delete obsolete.`
The Professional path returned the complete unsafe comma-boundary command
literally:

```text
Keep draft, then ship. Command correction, delete draft.
```

Independent review first found that an explicit punctuation list missed
quotes, brackets, slashes, and symbols. Interior deletion now requires
Unicode-alphanumeric neighbors on both sides, with only immediate sentence-tail
`.?!` accepted as a following exception. Byte-preserving regressions cover
curly quotes, brackets, slash, emoji, and both newline directions. The
independent re-review returned `SHIP` with no remaining finding at or above
80% confidence; its final focused gate passed 19 tests across four suites after
0.036 seconds.

## Claim boundary

No microphone, speaker playback, global event tap, clipboard, live insertion
target, app installation, process restart, or network/model download was used.
The retained synthetic voice proves stable namespace decoding and collision
behavior, not Aaron's natural pronunciation or daily-runtime field delivery.
